# Real public API v1 sample: text statistics

This source-built stdio LSP supplies one authentic command, `frost.sample.statistics`. It counts UTF-8 bytes, lines and whitespace-separated words from actual received open-buffer contents, grouped by document URI. It advertises no completion, rename, language diagnosis or debugger capability. It never reads project files or opens a network connection. `.frostnote` is a personal sample selector, not a claimed programming-language grammar.

A later authorized configure can enable `FROST_BUILD_EXTENSION_SAMPLE`; build the `frost-extension-text-statistics` target with the repository compiler/dependencies. No configure/build or sample execution was performed while authoring this slice.

After that build, prepare a personal manifest by running `prepare_manifest.py --executable <absolute built sample> --license <repository LICENSE> --dependency <required local runtime library> --output <new local JSON>`. Repeat the dependency option for each required runtime library. This helper only reads explicitly named files and writes a new manifest; it never launches the provider. Review the Apache-2.0 evidence and all runtime file hashes. The sample layout is flat and refuses duplicate basenames. Complete dynamic runtime inventories are the user's explicit responsibility; missing permissions/dependencies fail rather than relaxing the sandbox.

Use **Configure Extension Contributions**, import/review the prepared local JSON, and Save. Open a `.frostnote` inside a trusted project, wait for the actual provider initialize response, then choose **Run Extension Language Command → text-statistics/count**. The real provider result reports only received open-buffer data. Updating the document changes future statistics; disabling/removing the contribution cancels observations and retires the process. No tool is installed or downloaded by onboarding.

The sample opts into `sandbox.profile: read-only-stdio`: explicit pinned runtime files only, stdio, clean environment, no filesystem write grant and no network. Windows uses private staged copies, never original project/tool ACL changes; Linux enforcement capability is checked at native launch. Unsupported OS/kernel enforcement, missing runtime files or denied permissions are explicit launch failures. OS enforcement and normal product acceptance are authored but unexecuted. Existing generic LSP/DAP integrations retain their permissions unless explicitly opted into this profile.
