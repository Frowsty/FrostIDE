# 0123: Unity Test Runner in Unit Tests

Status: proposed; source implementation authored, runtime acceptance deferred.

The normal Unit Tests window exposes EditMode and PlayMode through the selected trusted Unity editor. Discovery and execution use the public TestRunnerApi in an optional Editor assembly, enabled for com.unity.test-framework versions [1.4.0,2.0.0). Missing framework support produces an explicit unavailable result. No source-text or generated-test fallback exists.

The entire tests:base64url(JSON) command is covered by the existing version-2 request MAC, with a 4096-byte command bound. Capability version 1, project, selected instance/session/generation, request identity, trust revision and revocation epoch are checked before publication. Requests name an observer owner, opaque job, catalog and exact framework UniqueName selections. The producer resolves these to unambiguous actual FullName filters; invalid selections never broaden to Run All. Execute returns the actual framework GUID used for cancellation and retained in observations. Lost acknowledgements are observed by exact job rather than retried.

Callbacks publish actual outcomes, duration and explicitly truncated diagnostics. Immutable snapshots contain at most 2048 cases in pages of eight, bounded identity/detail bytes and bounded tree depth/node count. A complete consistent snapshot is required before rows confer execution authority. Replaced domains cannot publish stale replies. A serialized editor-only observer retains ownership and the native API reference across ordinary PlayMode reload; reattachment requires the same instance, owner, job and execution identity.

Unity callbacks do not identify their execution GUID. This profile supports one ordinary owned run; observed foreign execution, duplicate RunStarted or compilation during a run invalidates attribution. Uncertain execution is not reported complete or silently retried; native Unity cleanup may be necessary. Cancellation acknowledgement means the API accepted cancellation, while RunFinished establishes completion. These controls do not exclude arbitrary native extensions starting concurrent runs, authenticate an OS process, or promise survival across editor restart.

Authored evidence includes strict response and normal-window tests, MAC tampering probes, and an offline producer public-API-double probe (`tests/unity/run_unity_tests_probe.py`, explicit installed SDK and scratch path). Doubles establish state-machine behavior only. Actual Unity acceptance remains required: use a disposable trusted Unity 6000 project with framework 1.4.x, parameterized passing/failing/ignored EditMode cases and yielding PlayMode cases; verify actual discovery, exact selected execution, failure stack navigation, Run Failed, native cancellation, domain reload reattachment, competing native run refusal and replacement-editor stale response rejection. Record actual framework GUID and callbacks. No Unity, SDK, build, configuration or test execution was performed for this source slice.

Public API: https://docs.unity3d.com/Packages/com.unity.test-framework@1.4/api/UnityEditor.TestTools.TestRunner.Api.TestRunnerApi.html
