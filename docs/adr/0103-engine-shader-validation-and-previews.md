# 0103: Engine-native shader validation and rendered previews

Status: accepted for source implementation; runtime acceptance deferred (2026-11-20).

FEC-14 requires the engine compiler's errors on source files. FrostEngine GLSL programs use `#type`, engine layout pragmas, root-relative includes and material feature variants. A separate stock GLSL server cannot establish whether those programs match the renderer's dialect and material layouts.

The authenticated Edit-only `shader.validate` command uses the existing engine ShaderPreprocessor and ShaderCompiler (engine glslang pin `vulkan-sdk-1.4.363.0`), and the actual MaterialSerializer, ShaderManager and MaterialManager for material programs and parameters. No compiler library enters the IDE process and no new package is introduced. No GLSL language server is selected or installed, so no additional GLSL-server licence decision is implied. The bounded native `shader.language` editing profile uses the same pinned glslang AST and resolved preprocessor include provenance. Normal completion, definition/declaration, hover and Structure actions use actual compiler declarations, use identities, member types and source ranges; idle diagnostics use actual compilation. Include completion and navigation use resolved engine paths. Dirty overlays, including retained documents without views, carry identity/version and dependency receipts. Completion recovery preserves source offsets and does not invent declarations. Include files require a successfully queried owning program; unsupported loop/switch completion scopes are withheld conservatively. Rename, references, formatting and exhaustive feature-permutation validation are not claimed. Native producer checkpoint: `08897089`. A future GLSL server needs its own pinned permissible licence ADR before integration.

The request carries the captured main source; includes use the selected physical project/engine shader root. Bounded successful and absent dependency receipts, exact source hashes, current editor images and the authenticated session/state identity guard publication. Dirty include buffers refuse rather than showing disk-derived errors against different editor text. Shader diagnostics have a separate Problems source.

`assets.preview` creates an isolated empty-content engine with the session's VFS and deserialized registry, without scanning project assets or repairing sidecars. Supported texture, material and sprite-sheet previews use the actual sprite/material renderer and bounded GPU readback. Missing/failed resources and unresolved texture/material fallbacks refuse. The command returns embedded PNG bytes, source/texture hashes and explicit dimensions; no image is inferred from asset names or assembled by the IDE. Private cache data is removed on shutdown. PNG decoding, encoded inputs, decoded texture dimensions/memory, frame counts and dependency counts are bounded. Previews are explicit snapshots of saved assets and the session registry, rather than live renderer ownership.

Trust revocation, session replacement, Edit-state transitions and editor changes invalidate pending observations and displayed results. Current-source checks also run after worker-side dependency checks. GPU-unavailable and unsupported asset cases remain explicit errors. Original compiler/include/material and genuine GPU readback fixtures are authored; no build, test, feature execution or WSL run establishes acceptance yet.
