# 0126: Explicit installed DXC diagnostics

Status: source implementation; independent review and runtime acceptance pending.

The normal action `DXC HLSL Diagnostics...` asks for an explicitly installed absolute compiler path, an existing saved `.hlsl` source in the trusted project, an entry identifier and a Shader Model 6 stage target. The profile is retained for the workbench session. This runs actual DXC, not a lexical substitute. Save All must complete. The command uses separate argv fields, HLSL 2021, the explicit entry/target and DXC's MSVC diagnostic format; compiled output goes to the null device. No download, PATH discovery, shell, response file or arbitrary extra-option field is involved. This deliberately narrow profile uses source-relative includes and the compiler's inherited environment; custom include roots/defines and Unity-generated variants require a future explicit profile extension.

A background worker uses IProcessLauncher under captured project trust revision. Cancellation, replacement jobs, trust revocation, project changes and shutdown revoke ownership; current trust and operation identity are checked before publishing. Output is merged and bounded during collection at 1 MiB, with a 30-second deadline and a 4096 diagnostic-row bound. Over-budget results are refused without partial publication. The primary source has a bounded stable snapshot (4 MiB), and open HLSL/HLSLI documents are compared with saved UTF-8 bytes before and after the command and with current editor bytes before publication (16 MiB aggregate). This is a saved-source compiler observation, not an atomic filesystem transaction: unopened/transitive includes and external concurrent filesystem writers are not leased, and DXC may resolve outside includes. Primary/open-file ABA changes cannot be detected. Diagnostics describe the saved files observed by the compiler, not a guaranteed immutable whole-project closure.

Actual compiler file, line, column, severity and message enter an independent DXC source in the normal Problems tool window. Locations are interpreted relative to the captured project directory. Exit status and compiler findings are distinct; launch errors and nonzero exits without parsed locations remain explicit failures with bounded raw output. Existing C++/engine diagnostics remain independent. The normal Cancel action ends owned collection; native termination failures can delay cleanup and are not a successful result.

ShaderLab is a host format: this action does not extract embedded programs, infer Unity keyword permutations, select a render pipeline, synthesize Unity macros, translate generated diagnostic locations or claim coverage of Unity shader variants. Users select an actual standalone HLSL translation unit and compiler profile.

Authored fixtures cover actual diagnostic format and location projection, explicit profile/refusal rules, exact real-command argv through a scripted launcher, streaming output refusal, cancellation-before-launch and trust revoke/regrant refusal. An opt-in `FROST_TEST_DXC` fixture compiles an actual saved invalid HLSL file with the explicitly configured installed compiler and checks its real failure/location/message. No compiler, build, configuration or test was executed for this source change. Product/SDK acceptance remains deferred.

DXC option source: https://github.com/microsoft/DirectXShaderCompiler/blob/main/include/dxc/Support/HLSLOptions.td (`-E`, `-T`, `-HV`, `-Fo`, `-fdiagnostics-format`). `-Zs` is small-PDB generation, not a syntax-only mode.
