# ADR 0109: Owned RoslynHost and authoritative SDK project context

- Status: accepted for source implementation; runtime and redistribution verification pending
- Date: 2026-11-20
- Plan: R17 LTR-2 through LTR-5; decision D41

Replace the default csharp-ls process with the repository-owned Apache-2.0 FrostRoslynHost. The supervised existing LSP transport, project trust gate, document versioning and REF1 preview/apply owner remain authoritative. The host uses actual MSBuildWorkspace evaluation, Roslyn compiler diagnostics, completion, QuickInfo, SymbolFinder, Renamer, Simplifier and Formatter; it never writes source documents. Source rename and code actions return WorkspaceEdit proposals, including versions for open documents. Unsupported metadata source navigation, arbitrary project creation and ambiguous linked semantic contexts refuse explicitly.

No new third-party version or feed is introduced. Microsoft.CodeAnalysis 5.9.0, Microsoft.Build.Locator and their runtime closure already have exact archive/nuspec/asset hashes, MIT/Apache-2.0 declarations and retained notices in sdk/managed-dependencies.json, audited under ADR 0064. The old pinned csharp-ls archive remains solely an offline provenance carrier for that graph; its server entry is excluded from the owned host's references and is never the default process. This avoids the proprietary Microsoft language-server distribution and vsdbg entirely. The SPDX allowlist and prior dependency gate are preserved; the gate has not been executed during implementation-first.

The SDK stays pinned to 10.0.403 with roll-forward disabled for host compilation. tools/roslyn_host.py first verifies the prior archived graph and installed assets, then builds only the owned source using an empty package-source configuration. It records every output and source-input digest. Bootstrap and fixture/staging routes use the owned host's receipt; no packages or tools are installed by tests. The implementation session does not execute this recipe, SDK commands, builds, tests or downloads.

The SDK snapshot command uses real dotnet MSBuild -getProperty/-getItem output with explicit project/configuration/TFM/RID authority, retaining item metadata and central-package/test facts. Evaluation performs no restore or build target, but imports are executable project code and require trust. Product loading and edits must retain captured workspace/trust generations; source edits never substitute XML glob guesses for evaluated Compile items.

RoslynHost startup requires a trusted workspace plus a managed project context, a solution containing a C# project, a supported Unity context, or a C# document. Opening a C# document later activates RoslynHost in a trusted folder.

Self-authored Apache-2.0 fixtures cover linked and removed Compile items, inner/outer target frameworks, nullable/compiler context and central package definitions. Later real-tool acceptance compares evaluated items to MSBuild, semantic replies to direct Roslyn and applied rename/code actions to an actual dotnet build. This ADR records implementation scope and provenance, not completed runtime acceptance.

The small MoreLINQ 4.4.0 upstream corpus is pinned to tag v4.4.0, commit 6d97c3b1d482f98300f4446df14742b0e3fafbec in tests/corpus/corpora.lock.json. The [official release](https://github.com/morelinq/MoreLINQ/releases/tag/v4.4.0) supplies the commit link; [COPYING.txt at that tag](https://raw.githubusercontent.com/morelinq/MoreLINQ/v4.4.0/COPYING.txt) declares Apache-2.0, already on the existing SPDX allowlist. The future fixture uses an owned copy and a local pinned-SDK global.json override, retaining original source and framework definitions. No source corpus was fetched or executed during this session.


The R17 semantic refactoring profile composes only the installed Roslyn Extract Method and Move Type To File exports from the same MEF container as MSBuildWorkspace. It reads their ApplyChangesOperation solutions and never invokes operations, option dialogs or workspace writes. Extract eligibility and data flow belong to the actual provider. A bounded private static signature action swaps the first two required value parameters; actual invocation arguments acquire their bound parameter names without reordering evaluation, all targets are rebound, and overload sets, method groups, recursive/overlapping edits and unsupported signatures refuse. Private declaration deletion requires no actual source references, a single declaration and no attributes; fields must be static and uninitialized. This is source-reference safety, not a reflection/serialization reachability claim.

Owned actions carry bounded source/project before-images into a dedicated managed adapter. Whole semantic groups preview as one REF1 transaction with source identity/version, physical containment, trust, selected evaluation and service-generation revalidation. The retained requester captures immutable context at GUI registration and stamps its original identity on asynchronous responses; stale popup actions refuse even with unchanged source, and worker requests never access Workbench state. The journaled coordinator owns multi-file failure recovery and global Undo/Redo. Generic WorkspaceEditApplier still rejects owned resource metadata and standard LSP resource operations remain unsupported. Existing rename/simplify caller responses remain unchanged.

Move type/file accepts one new or renamed same-directory C# endpoint in the selected non-linked project. Renames require unchanged source and distinct absent endpoints; case-only moves refuse. Project membership is explicitly updated in the same transaction only for unconditional Microsoft.NET.Sdk project files without custom imports, targets, Compile metadata or inherited Directory.Build overrides. Other project profiles refuse; linked/shared source mutation is withheld until all-context propagation exists. Original normal Alt+Enter, preview, Undo/Redo, occupied-endpoint refusal, compiler action and post-refactor build fixtures are authored. No build, test, feature execution or WSL run establishes acceptance.
